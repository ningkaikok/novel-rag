# 检索是否真的在起作用：模型记忆 vs 上下文依据

## 要回答的问题

之前拿《诡秘之主》测三个模型,两个答对、一个答错,很容易得出"检索系统有效"的结论。
但这个结论有一个致命漏洞:**《诡秘之主》是读者量级巨大的网络小说,几乎必然出现在
大模型的训练语料里**。模型答对,完全可能是**背出来的**,跟这套检索系统喂给它的
片段毫无关系——如果是这样,那检索环节其实是摆设,只是"看起来"起了作用。

要把"模型自己的记忆"和"检索真的在起作用"这两件事分开,不能只看"答对没答对",
需要设计对照实验。这份报告记录两组测试和结论。

## 实验设计

| 组 | 语料 | 变量 | 排除的可能性 |
| --- | --- | --- | --- |
| **C** | 雾隐山庄(项目原创短篇,只存在于这个仓库里,不可能出现在任何模型的训练语料中) | 给不给检索到的原文 | "模型背过这本书" |
| **D** | 诡秘之主(热门公开小说,模型很可能背过) | 检索到的内容是真的还是被篡改的 | "模型选择性无视上下文、靠记忆答题" |

C 组回答"背没背过"；D 组回答更关键的问题——**就算模型可能背过这本书,它这一次
的回答用的到底是自己的记忆,还是你喂给它的那段文字**。D 组是标准的 RAG 忠实度
(faithfulness)测试手法:故意给模型一段被篡改的"事实",如果模型跟着篡改的内容走,
说明它真的在依据你给的上下文；如果模型无视篡改、给出"正确"答案,说明它压根没在用
你给的东西,你的检索系统是摆设。

三个模型均测试:`claude:sonnet`、`glm:glm-4.6`、`qwen2.5:7b`(本地)。

## 组 C 结果:雾隐山庄

问题:"沈砚之的师父和顾长风是什么关系？他们当年为什么反目？顾长风得的是什么病？"

**条件 A(不给任何检索内容,自由问答模式)**——三个模型全部明确拒绝瞎编:

| 模型 | 回答摘要 |
| --- | --- |
| claude:sonnet | "我这里无法确认……凭通用知识编出来的情节都可能是虚构、不准确的，容易误导你。" |
| glm:glm-4.6 | "并非通用常识中具有固定背景的公版人物，我无法仅凭通用知识准确回答……" |
| qwen2.5:7b | "我没有具体的小说内容或背景信息来直接回答这些问题……" |

**条件 B(给检索到的真实原文,grounded 模式)**——三个模型全部答对,细节一致:
沈砚之的师父与顾长风是三十年前的师兄弟,因追查黑市贩卖"蚀骨散"而反目;
顾长风所患正是这种奇毒,寻常药石无法根治。三个模型的措辞略有差异,但事实点全部
正确、且都标注了引用编号 `[1][2]`。

**结论**:这本书**保证**不在任何模型的训练数据里。三个模型在没给内容时全部诚实
拒答,给了内容后全部答对——这是"检索确实在提供模型原本不掌握的信息"最干净的证据。

## 组 D 结果:诡秘之主(篡改关键事实)

取 `chunk_id=10331`(第二十一章 第三位)里的一句关键事实——原文写明罗塞尔·古斯塔夫
穿越前的真实姓名。把这个人名替换成一个虚构的假名后,单独把这一段喂给模型
(不经过检索流程,直接构造 prompt),问:"根据这段内容,罗塞尔·古斯塔夫穿越前的
真实姓名是什么？只回答姓名。"

| 模型 | 真实文本 → 回答 | 篡改文本 → 回答 | 判定 |
| --- | --- | --- | --- |
| claude:sonnet | 真实姓名`[1]` | **篡改后的假名**`[1]` | ✅ 跟着给定文本走 |
| glm:glm-4.6 | 真实姓名`[1]` | **篡改后的假名**`[1]` | ✅ 跟着给定文本走 |
| qwen2.5:7b | 真实姓名`[1]` | **篡改后的假名**`[1]` | ✅ 跟着给定文本走 |

**三个模型全部跟着篡改后的文本回答,没有一个模型"坚持"用书里的真实设定纠正它。**

这个结果比组 C 更有说服力,因为它排除了一个更隐蔽的可能性:哪怕模型确实背过
这本书的剧情，**在这次具体的问答里，它用的还是你给它的那段文字，不是记忆**。
如果测试反过来——模型无视篡改、给出真实剧情里的人名——那才说明检索片段被模型
晾在一边了，你的检索系统白做了。

## 结论

1. **组 C 证明**:面对模型训练数据里绝对没有的内容,答案的正确性完全来自检索到的
   原文,不给原文时模型会诚实拒答而不是瞎编。
2. **组 D 证明**:面对模型可能已经"背过"的热门小说,当前这套 prompt 设计
   (`[编号] 原文片段` 的格式 + 明确指示"仅根据提供的原文片段回答")足够让三个
   模型都优先服从给定上下文,而不是绕过检索片段去调用自己的训练记忆。
3. 合起来看:**这套 RAG 系统里"检索"这一步不是摆设**——不论语料是模型没见过的
   还是模型可能见过的,最终答案都是由送进 prompt 的那段文字决定的，不是模型自己
   在"表演"。这也解释了为什么之前的重排、Contextual Retrieval 等优化能带来
   实测可见的效果提升——如果模型压根不看检索内容，那些优化理应对最终答案毫无影响。

## 方法论上的一点提醒

这次组 D 的"篡改测试"是事后专门设计来堵住组 C 留下的漏洞的——组 C 单独看
似乎已经能说明问题，但雾隐山庄和诡秘之主是两种完全不同性质的语料，直接把组 C
的结论套到诡秘之主这类热门小说上是不严谨的。**测试对象本身有没有可能"污染"结论
（这里是"模型可能背过热门小说"），需要在设计阶段就想到，而不是等结果出来后才怀疑。**
