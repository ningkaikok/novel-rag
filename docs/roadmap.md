# 项目路线图

路线图按“先建立可评测闭环，再增加能力”的顺序排列。每个里程碑只有满足验收标准
才算完成；未进入当前里程碑的功能不提前引入依赖。

## M0：统一问答入口与路径路由（已完成）

- [x] 单输入框支持自动判断、仅依据原文、自由问答
- [x] 自由问答不依赖小说索引
- [x] 思考过程展示实际路径和原因
- [x] 后端单元/接口测试与前端端到端测试
- [x] 离线路由评测集和评测脚本

验收：开放问题不触发检索，小说问题仍走现有混合 RAG，用户可以显式覆盖自动判断。

## M1：章节元数据与可核验引用（已完成）

- [x] 切分时识别章节标题，保存 `chapter_title`，并保留全书片段编号用于定位
- [x] 出处卡片显示书名、章节名和片段编号
- [x] 回答中的 `[1]` 引用能定位并高亮支持它的原文
- [x] 增加引用编号有效性、证据关键词覆盖率和人工支持性复核字段

验收：用户能从答案中的每个事实跳到对应章节原文；旧索引可通过一次重建迁移。

实现与评测说明见 [章节元数据与可核验引用](citations-and-chapters.md)。

## M2：增量索引与后台任务体验（已完成）

- [x] 按文件内容哈希识别新增、修改和删除的小说
- [x] 只重建发生变化的书，保留其他书的索引
- [x] 前端显示切分、Embedding、BM25、入库阶段和进度
- [x] 支持取消任务、失败原因和安全重试

验收：增加一本书不再清空全库；任务中断不会留下半套向量/BM25 索引。

实现与一致性说明见 [增量索引与后台任务](incremental-indexing.md)。

## M3：全书和跨书问题（已完成）

- [x] 建立“片段 → 章节 → 全书”的层级摘要
- [x] 自动识别局部事实问题和全局分析问题
- [x] 摘要命中仍回到原文证据参与 RRF 与重排
- [x] 增加主题、人物成长、跨书比较结构评测集

验收：全书问题不再依赖少量 top-k 片段碰运气，同时保持出处可核验。

实现说明见 [M3 层级检索](hierarchical-retrieval.md)，结构评测运行
`python scripts/eval_hierarchy.py`。

- [x] trace 记录向量与 BM25 的候选名次、分数和耗时
- [x] trace 记录 RRF 排名和进入重排的候选
- [x] 重排记录 `previous_rank` 和最终入选状态

## M5：部署与多用户边界

- [ ] Docker Compose 一键启动应用、PostgreSQL 和 pgvector
- [ ] 上传大小、文件类型和资源配额限制
- [ ] 用户、书架、索引和会话隔离

验收：从“本机单用户学习项目”升级时，数据和权限边界清晰，不依赖默认可信环境。

## M6：Agent 平台化与生产边界（规划中）

这一阶段不是立刻引入一整套微服务，而是把当前 Agent Lab 的五个只读工具逐步拆成可
注册、可授权、可观测、可恢复的边界。先用普通 Python 保持学习链路透明，再按真实
需求评估 MCP、OpenTelemetry 和 LangGraph。

- [ ] M6.1：建立轻量 Control Plane，用统一 `ToolSpec` / Tool Registry 管理 schema、版本、
  权限、风险等级、超时和启停；运行时只读取经过验证的不可变快照
- [ ] M6.2：增加 Tool Gateway，集中做鉴权、参数校验、出站白名单、Prompt Injection
  隔离、限流、超时、幂等、分类重试、熔断和审计
- [ ] M6.3：增加 Model Gateway，统一 Ollama、Claude 和智谱适配，记录 token/耗时/成本，
  支持按任务选模、预算上限、超时和显式降级
- [ ] M6.4：统一 Agent 事件，串起 Router、Planner、Tool、检索、LLM 和 SSE 的 `run_id`；
  同时建立路由准确率、工具成功率、答案依据率、延迟和成本的评测闭环
- [ ] M6.5：拆分 Chat History、Run State 和 Event Log；短问答继续 SSE，长任务改为
  `job_id + worker`，并补 checkpoint、幂等、取消、恢复和死信处理
- [ ] M6.6：在工具需要跨客户端复用时增加 MCP 适配，不绕过内部权限和审计边界
- [ ] M6.7：结合 M5 完成租户隔离、配额、数据保留/删除、备份、结构化日志、监控告警
  和灰度发布；高风险写工具默认需要人工审批

阶段性验收：五个现有工具都从统一 Gateway 执行；外部文本中的指令不能越权触发工具；
一次 Agent 运行可以按 `run_id` 还原完整事件顺序并计算质量、延迟和成本指标；权限错误、
参数错误、超时和下游失败可区分；恢复任务不会重复执行有副作用的工具；模型供应商失败
时按显式策略降级而不是静默换模型。只有在出现跨进程恢复、人工审批、复杂分支或长任务
时，才把已测试的编排函数迁入 LangGraph。

架构边界和迁移示例见 [Agent 平台化架构](agent-platform-architecture.md)。

## 暂不进入路线图主干

- **LangGraph**：M6.5 之前不引入；已有五步教学工具循环仍用普通 Python，等需要人工
  暂停恢复、跨进程检查点、并行分支或更复杂重试时再复审。
- **多 Agent**：没有评测证明单流水线无法解决之前不增加。
- **更换向量数据库/搜索引擎**：先用 PostgreSQL 把检索和产品闭环做完整。
