# 项目路线图

路线图按“先建立可评测闭环，再增加能力”的顺序排列。每个里程碑只有满足验收标准
才算完成；未进入当前里程碑的功能不提前引入依赖。

## M0：统一问答入口与路径路由（已完成）

- [x] 单输入框支持自动判断、仅依据原文、自由问答
- [x] 自由问答不依赖小说索引
- [x] 思考过程展示实际路径和原因
- [x] 后端单元/接口测试与前端端到端测试
- [x] 离线路由评测集和评测脚本

验收：开放问题不触发检索，小说问题仍走现有混合 RAG，用户可以显式覆盖自动判断。

## M1：章节元数据与可核验引用（已完成）

- [x] 切分时识别章节标题，保存 `chapter_title`，并保留全书片段编号用于定位
- [x] 出处卡片显示书名、章节名和片段编号
- [x] 回答中的 `[1]` 引用能定位并高亮支持它的原文
- [x] 增加引用编号有效性、证据关键词覆盖率和人工支持性复核字段

验收：用户能从答案中的每个事实跳到对应章节原文；旧索引可通过一次重建迁移。

实现与评测说明见 [章节元数据与可核验引用](citations-and-chapters.md)。

## M2：增量索引与后台任务体验（下一阶段）

- [ ] 按文件内容哈希识别新增、修改和删除的小说
- [ ] 只重建发生变化的书，保留其他书的索引
- [ ] 前端显示切分、Embedding、入库阶段和进度
- [ ] 支持取消任务、失败原因和安全重试

验收：增加一本书不再清空全库；任务中断不会留下半套向量/BM25 索引。

## M3：全书和跨书问题

- [ ] 建立“片段 → 章节 → 全书”的层级摘要
- [ ] 自动识别局部事实问题和全局分析问题
- [ ] 摘要答案仍能回溯到原文证据
- [ ] 增加主题、人物成长、跨书比较评测集

验收：全书问题不再依赖少量 top-k 片段碰运气，同时保持出处可核验。

## M4：人物关系图质量闭环

- [ ] 关系边保存方向、置信度和来源片段
- [ ] 增加人工审核与修正界面
- [ ] 区分“同段共现”和“明确关系陈述”
- [ ] 只有达到质量门槛后才考虑默认开启

验收：伴侣/师徒评测不再把普通同框人物当成确定关系，且每条边可以追溯原文。

## M5：部署与多用户边界

- [ ] Docker Compose 一键启动应用、PostgreSQL 和 pgvector
- [ ] 上传大小、文件类型和资源配额限制
- [ ] 用户、书架、索引和会话隔离
- [ ] 备份恢复、结构化日志和基础监控

验收：从“本机单用户学习项目”升级时，数据和权限边界清晰，不依赖默认可信环境。

## 暂不进入路线图主干

- **LangGraph**：等出现工具循环、人工暂停恢复或跨进程检查点需求再复审。
- **多 Agent**：没有评测证明单流水线无法解决之前不增加。
- **更换向量数据库/搜索引擎**：先用 PostgreSQL 把检索和产品闭环做完整。
