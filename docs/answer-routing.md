# 问答模式与自动路由

## 用户看到的三个模式

项目仍然只有一个输入框，模式选择只改变后端如何取得依据：

| 模式 | 是否搜索小说 | 适合的问题 |
| --- | --- | --- |
| **自动判断** | 由规则决定 | 默认选择；小说问题和开放问题混合使用 |
| **仅依据原文** | 强制搜索 | 人物、剧情、原句和需要可靠出处的问题 |
| **自由问答** | 不搜索 | 技术概念、写作、翻译、闲聊等通用任务 |

实际选择的路径会作为第一条“思考过程”显示。自由问答会发送空的 `sources` 事件，
不会伪造小说出处；即使书架为空或索引尚未建立也能使用。

## 为什么自动路由是保守规则

人物名没有有限词表可以列完。例如“韩立的师父是谁”没有“小说”“原文”等显式词，
但显然应当查书架。因此自动模式只把高置信度开放问题判为自由问答：

1. 用户明确说“不用搜索”；
2. 问候、助手使用帮助；
3. 明确的技术概念、天气等通用知识；
4. 明确的写作、翻译、润色任务。

包含书名号或小说内容词时强制走原文；其余拿不准的问题默认走原文。规则判断免费、
稳定且容易评测，不会为了省一次检索而额外调用一次路由模型。

## 代码入口

| 文件 | 职责 |
| --- | --- |
| `src/query_router.py` | 模式枚举、路由规则、自由问答 prompt |
| `backend/schemas.py` | `/api/ask` 的 `mode` API 契约 |
| `backend/main.py` | 在索引检查和查询改写之前应用路由 |
| `frontend/src/App.tsx` | 同一输入框旁的模式选择器 |
| `tests/routing_test_set.json` | 离线路由评测集 |
| `scripts/eval_routing.py` | 不依赖模型和数据库的评测脚本 |

## 如何评测和扩展

```bash
python scripts/eval_routing.py
pytest -q tests/backend/test_query_router.py
```

增加规则时先加反例。例如要识别新的技术问题，除了加入“某技术是什么”，也要加入
一个包含相似词的小说问题，避免规则变宽后把小说问答送进自由模式。

如果未来真实问题的规则误判率明显上升，可以加一个轻量模型作为**不确定样本的兜底**，
但仍保留显式模式覆盖、离线评测集和路由原因展示。这里只是一个有条件的分类步骤，
仍不构成引入 LangGraph 的理由。
