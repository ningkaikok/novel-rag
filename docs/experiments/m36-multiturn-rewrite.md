# M3.6 第一步：多轮追问的查询改写评测

- 日期：2026-09-05
- 标注集：`tests/multiturn_test_set.json`（22 条，覆盖路线图要求的五个类别 +
  一个"不该改写"负例类别）
- 工具：`scripts/eval_multiturn.py`
- 语料：全部来自仓库原创文本（`tests/ci_corpus/沙海航灯.txt`、
  `tests/ci_corpus/青梧镇异闻.txt`、`data/novels/雾隐山庄.txt`），不含版权小说原文

## 为什么先做这一步

路线图 M3.6 的推荐顺序是"先完成查询改写评测，再增加 token 预算和滚动摘要"。
理由在做完之后显得更充分：**评测立刻测出了一个比"没有记忆"更严重的现存 bug**，
如果先去加会话摘要，只会在一个已经会偷换问题的改写器上叠更多上下文。

## 评测方法

断言是确定性的字符串包含/排除，**不引入 LLM 评委**：

```
expect_contains  改写后必须出现（通常是被解析出来的实体）
expect_absent    必须不出现（通常是上文里那个错误的对象）
should_rewrite   这条该不该触发改写（自足问题为 false，不改才是对的）
```

改写的产物是"拿去检索的问题"，成败可以被机械验证。引入评委只会把一个可判定的
问题变成又一个需要校准的问题——M3.5 的教训摆在那里：Judge 自己的一致率只有 67.9%。

标注集刻意利用了原创语料之间天然的同名/近名陷阱：

- **顾长风**：《青梧镇异闻》里是钟表匠师父，《雾隐山庄》里是中毒的老医师，两个人
- **沈砚秋**（青梧镇） vs **沈砚之**（雾隐山庄）：只差一个字

## 结果

同一套断言下的前后对比（改写模型 `glm:glm-4-flash`）：

| 类别 | 修复前 | 修复后 |
| --- | --- | --- |
| 指代 | 5/5 | 5/5 |
| **否定** | **3/4** | **4/4** |
| 时间顺序 | 3/4 | 3/4 |
| **纠正上一轮** | **1/3** | **2/3** |
| 跨书切换 | 4/4 | 4/4 |
| 不该改写 | 2/2 | 2/2 |
| **合计** | **18/22 = 81.8%** | **20/22 = 90.9%** |

触发判断（不调模型，零成本）：20/22 → **21/22 = 95.5%**。

## 测出来的真问题：改写会偷换用户问的主语

这是本轮最重要的发现，**它比"回答里没有历史"更严重**——因为它会悄悄回答另一个问题：

| 用户问的 | 修复前改写成 |
| --- | --- |
| **巴特尔**能牵它吗？ | **陆知微**能牵它吗？ |
| **陈伯**送了他什么谢礼？ | **白先生**送了他什么谢礼？ |

根因：原提示词只写了"把指代替换成历史里对应的具体名字"，**没有写"用户已经明确
写出来的名字绝对不能动"**。模型于是从上文里挑了个更显眼、出现更多的人名，把用户
亲口写的那个覆盖掉了。

两条都出现在"否定"类别不是巧合：这类追问的句子结构里，用户写的主语往往不是上文
最显著的那个实体（"除了陆知微谁牵它都要挨一口" → 用户问的却是巴特尔），
正好落在这个 bug 的射程内。

## 三处修复

1. **禁止替换用户写出的名字**（提示词加硬约束 + 正反例）——修好了上面两条
2. **纠正句式的形状说清楚**：`不是 A，是 B` 的结果里不能再出现 A；A 可以是人
   （不是小何，是会修车的），也可以是方面（不是问结局，是问开头），一样要丢掉
3. **优先用人名而不是身份描述**："小顺"而不是"杂货铺的伙计"——改写结果是拿去做
   关键词检索的，名字能命中 BM25，身份描述命不中

触发侧补了纠正句式的词（`不对`/`不是问`/`我问的`/`我说的`/`而是`）。刻意没有加
裸的「不是」——它在自足问句里太常见（"蚀骨散是不是很难解"），会造成大量无谓调用。

### 中途踩到的一个权衡

第 3 条（优先人名）修好了 `mt_time_04`，却让 `mt_fix_03` 回退了——模型往一个
根本没有指代词的纠正句里硬塞了人名（"小顺不是问结局，是问开头"）。补上第 2 条
把纠正句式的目标形状说清楚之后才同时成立。**这类互相干扰只有评测集能发现**，
靠单条手工试是看不出来的。
