# 前端渲染性能自查清单

评估的是**流式输出时界面是否卡顿**（打字机、重渲染、滚动），不是回答质量（质量见 `TEST_REPORT.md`）。

## 衡量指标

主线程「长任务」——一次执行超过 50ms 的任务会阻塞渲染、让用户感到卡顿。
在浏览器控制台里装观察器，跑完一次流式回答后读数：

```js
window.__lt = [];
new PerformanceObserver(l => l.getEntries().forEach(e => __lt.push(Math.round(e.duration))))
  .observe({ entryTypes: ["longtask"] });
// …发一个问题，等它输出完，再看：
JSON.stringify({ 次数: __lt.length, 超100ms: __lt.filter(d=>d>100).length, 最长ms: Math.max(0,...__lt) });
```

**通过标准**：一次完整回答期间 `超100ms === 0`，`最长ms` 尽量接近 0。
（本轮修复后实测：GLM-4.6 持续输出 90s+，长任务次数 = 0。）

> ⚠️ 别在 `javascript_tool` / 控制台里用 `await sleep(几十秒)` 去「等」——会把调用卡到超时。
> 装好观察器后，发送和读数分成**多次独立、瞬时**的调用，让浏览器事件循环自己跑。

## 测试问题集（每条针对一种渲染压力）

| # | 问题 | 建议模型 | 考察点 |
|---|------|---------|--------|
| P1 | 雾隐山庄的庄主是谁？ | 任意 | 短答案基线：小渲染量，确认无回归 |
| P2 | 详细讲讲诡秘之主里克莱恩的经历，越详细越好。 | GLM-4.6 / opus | 长答案：打字机 + 逐帧重渲染 + 自动滚动的主压力场景 |
| P3 | 简述克莱恩的身份。 | GLM-4.6 | 思考静默期：确认「正在翻书思考…」在正文到达前出现 |
| P4 | 这本书主要讲了什么？ | GLM-4-Flash / 本地 | 高吞吐：token 极快到达，考察前端队列匀速吐字、不掉帧 |
| P5 | 连续追问 5 轮（任意问题） | 任意 | 多轮：验证 `React.memo` 生效——旧气泡不随新回答重渲染 |
| P6 | 把「参考原文段数」调到 10 再问 P2 | GLM-4.6 | 多出处：验证出处卡片的独立 memo，5~10 个省略号组件流式期不重测量 |

## 每种场景该看到什么

- **P2/P6（长答案 + 多出处）**：打字匀速、页面不抖、往上翻看出处不会被强行拽回底部；长任务 0。
- **P3（慢推理模型）**：发送后先出现三点跳动的「正在翻书思考…」，第一个字到达即切成正文 + 光标。
- **P4（快模型）**：出字快但仍是匀速打字（前端排队），不会整段"蹦"出来也不掉帧。
- **P5（多轮）**：React DevTools Profiler 里，流式那一刻只有最后一个气泡在重渲染，历史气泡不亮。

## 想更跟手时的模型选择（与界面无关）

- 追求丝滑即时：`GLM-4-Flash`（免费）或本地 `qwen2.5`。
- 追求质量、不赶时间：`GLM-4.6` / `claude:opus`，但它们会先思考数秒（P3 的思考指示就是为这段准备的）。
